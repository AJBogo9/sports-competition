# Smoke run, 2026-09-08

The first run of [docs/SMOKE.md](../SMOKE.md) against a live bot, driven from Telegram Web on the
owner's own account, on the dev compose stack, after commit 194e594. One account, one test group,
a Tuesday in week 7 of the placeholder window. Bot: `@sports_competition_bot`.

**Environment note.** The university network resolves `api.telegram.org` to an Aalto address that
never answers, so the bot hung before polling. A local, untracked `docker-compose.override.yml`
pins the API's real IPv4 for the bot service; README's Deploy section records it. The machine also
suspended for about fifty minutes mid-run, which produced one `tick skipped: previous tick is still
running` line (the in-flight closing post's socket died); a restart cleared it and the post went
out. That line is therefore not evidence of a slow tick.

## Found and fixed during the run

1. **"Today instead" and "Log again" rendered a bare prompt**, without the logged-already line and
   without the yesterday button. Every prompt now comes from `checkInMessage`, which takes the date.
2. **The season winner's own closing post read "Prodeko wins the season, with Prodeko 1st of 9."**
   The placing clause is dropped when the reader is the winner (identity, not rank).
3. **`/me` after the end said "1st of 9 this week" under a "Final week" label.** Now "in the final
   week".

## Not run, and why

- The daily reminder at its hour, the five-ignore follow-up, and blocking: they need hours to pass
  or a second account, and the follow-up copy and the state machine are unit tested.
- The pin success path: the re-added bot is not an admin of the test group and promoting it through
  Telegram Web was not worth the time; the same code pinned successfully on 2026-09-07 (the old pin
  is still in the group), and the refusal path was exercised today.
- Fresh registration, the nine-guild picker on a bare `/start`, move and stay, non-admin refusals,
  the anonymous-admin question, and the `startgroup` deep-link order: all need a second account.
- The day-old and two-day-old stale prompts, and a Monday backdate into last week: need days to pass.
- `scripts/dump.sh` and `scripts/restore.sh`: not run today; the restore-fidelity test covers the
  content and now includes `target_minutes`.
- Whether the celebration's big animation plays for the recipient: not observable from the DOM.
  The reaction itself is confirmed.

Test suite after the fixes: 358 pass, 0 fail; `bunx tsc --noEmit` clean; config restored to the
real placeholder dates.
